# 0.6.0 本地迁移与回滚

正式版使用稳定目录 `%APPDATA%\Polar Vocab\Capture`，SQLite 为该目录中的 `captures.sqlite`。设置页会显示实际队列目录。Electron/Chromium 的 `userData` 与缓存位于同级 `Capture.runtime`，不提前写入队列迁移目标。无需用隔离启动器日常运行；开发和自动化测试仍可用 `POLAR_VOCAB_CAPTURE_DATA_DIR` 指定全新测试目录。

旧默认目录 `%APPDATA%\Polar Vocab Capture`、0.4.0/0.4.1 程序、0.5.0 候选及其独立目录都保留，不清理或重置。新版数据库 `PRAGMA user_version=2`，旧程序的版本护栏会拒绝打开；不要手动让旧版使用新版数据库。

## 首次启动的处理

1. 只在正式目录尚未建立队列时，检测旧默认目录中的 `captures.sqlite`。
2. 旧源以只读连接打开，检查 SQLite 完整性、版本、事件/设备身份、批次及回执关系。
3. 使用 SQLite 在线备份 API 建立完整一致快照，包含已提交的 WAL 内容；不直接复制正在使用的主数据库文件冒充完整备份。
4. 备份再复制为迁移副本，只在副本升级到版本2。逐项核对事件、冻结批次、回执、设置和设备ID，原事件正文及身份不补写、不重新生成。
5. 新目标在准备目录中校验完毕后发布。备份和回滚说明随新目录保留；原目录不改写。

如果旧默认目录没有 SQLite，创建新的正式空队列。**这不等于已经迁入其他测试目录的数据。** 本次开发的只读检查中，旧默认数据库不存在；当前用户是否已经完成正式迁入，以应用的迁移结果和最终整合报告为准，不能用人工测试的通过状态代替。

版本过新、文件损坏、批次不一致、身份缺失或已存在资料但缺少数据库时，停止并保留原文件。不会因失败创建空库覆盖历史，也不修改原始规划及历史报告。

## 从0.4.1或0.5.0独立目录迁入

如果此前使用的是独立候选目录，请在正式版开始收藏新词前执行：

1. 打开「设置 → 本机数据与迁移」。
2. 点击「从旧队列迁入（仅空库）」。
3. 选择旧 `captures.sqlite` 所在的**文件夹**，核对后选择「备份并迁入」。程序会关闭本次连接、清除该连接记住的凭证，停止读取/同步，迁移成功后重启。
4. 重启后核对队列数量和待上传状态，再按需要重新授权。源目录、旧程序和备份仍保留。

项目中此前提供的候选位置包括：

- `artifacts/desktop/hotkey-fix-0.4.1/test-data-0.4.1-20261026-c0807fb0/`
- `artifacts/desktop/dictionary-0.5.0/test-data-0.5.0/`

这只是帮助定位，不代表两个目录都要迁入。应用不扫描并合并所有 `.cache`、验收目录或不同设备的队列。每个队列有自己的设备身份和原冻结批次；随意混并会破坏身份与回执关系。

目标已有事件或批次时会拒绝迁入。不要为启用按钮而清空新队列；保留两边数据与导出备份，另行安排受控迁移。源与目标相同、直接以旧v1目录作为新版覆写目录，也会拒绝，不能作为绕过迁移的启动方式。

请结束旧版的日常使用，避免快照建立之后继续在旧队列新增词。在线快照不会持续跟随旧程序之后的写入；新增仍保留在旧目录，不会自动混入正式队列。无需删除旧目录或旧程序。

## 备份和中断恢复

每次迁移在新目录的 `migration-backups/<迁移UUID>/` 下保留资料：

| 文件 | 作用 |
| --- | --- |
| `source.sqlite` | 迁移源的完整在线备份，保留原数据库版本 |
| `manifest.json` | 版本、数量、源及迁移后逻辑摘要和文件校验值，不保存Token或词条明文到日志 |
| `ROLLBACK.txt` | 该次迁移的回滚说明及源位置 |
| `target-before.sqlite` | 向已存在空目标迁入时，目标迁移前的完整备份 |
| `retained-target/` | 上述迁入时保留的原目标DB及其存在的WAL/SHM文件 |
| `pending-*.json` / `recovery-*.json` | 发布及恢复证据，使用独立名称保留，不自动覆盖旧证据 |

向空目标迁入时，先写恢复journal，再保留原目标文件并发布新副本。启动检测到 `migration-pending.json`，会核对已发布副本；如果新副本已经完整发布则完成记账，否则恢复原目标。无法证明恢复安全时停止，不强行打开或重建空库。所有源、备份及失败副本保留，便于后续核查。

空的 `user_version=0` 元数据预置文件仅用于初始化/测试兼容，初始化前仍会建立备份；未标版本但已经含事件或批次的数据库不会当成新库处理。

## 回滚方法

1. 从托盘正常退出新版，保留新版队列与所有迁移备份。
2. 优先使用**未改写的原旧目录**及其匹配的旧程序。原目录已经保留，通常无需覆盖恢复任何文件。
3. 如果必须使用备份，复制该次 `source.sqlite` 到另一个空文件夹，并改名为 `captures.sqlite`，用匹配的旧程序打开该副本。不要覆盖任何已有队列，也不要把版本2的新版库交给旧版。
4. 如果迁移后已在新版收藏新词，两边都有独立数据。先分别保留完整备份，不能把旧快照覆盖回正式目录当作「回滚」，否则会丢失迁移后的新词。

不要只复制活跃队列的主文件、删除WAL/SHM、编辑事件ID或重新生成原冻结批次。SQLite自己的正常关闭/checkpoint可能改变这些文件的物理字节；活跃队列应比较在线快照中的原事件、批次与回执，不能仅靠WAL/SHM哈希判定数据是否保留。
