# 0.6.0 桌面安全授权与自动恢复

桌面授权由 `authorization.ts`、`credentials.ts` 和 `native/CredentialHelper.cs` 实现，使用当前 Windows 用户的 Credential Manager。它与 Web 页面的内存 PAT 授权不同，不修改 GitHub 同步协议，不自行创建 Token 或扩大仓库权限。

## 首次连接

1. 在设置填写 owner、私有仓库名和分支，核对顶部实际连接目标。历史验收使用 `Polar0216/polar-vocab-data-test / main`；2026-10-27用户另明确授权全是测试数据的 `Polar0216/polar-vocab-data / main`，最新真实验收仅操作后者。不得由此推定可测试其他仓库或真实学习数据。
2. 点击「输入凭证并测试（系统窗口）」。应用打开独立原生 WinForms 授权窗口，显示目标并用密码框接收 PAT；它是本应用的原生输入窗口，不是 GitHub 登录或 Windows 安全桌面。
3. 本人输入 Fine-grained PAT：只授权所选私库，Contents 读写，Metadata 默认只读，有限有效期，不加无关权限。不要输入到聊天、终端或项目文件。
4. 先执行只读检查，核对目标和队列数量，再确认连接。只有明确勾选「记住此设备」并确认后，才将凭证交给 Windows 凭证管理器保存；未勾选则只在本次主进程会话使用。

取消授权窗口或预检会保留本机队列。旧连接存在时，取消新的预检不替换旧连接；断开或输入代次变化后，迟到的结果不得恢复已取消会话。

## 存储边界

| 信息 | 保存位置 |
| --- | --- |
| PAT 和目标绑定记录（选择记住时） | Windows Credential Manager，当前用户、当前本机的 Generic Credential |
| owner / repository / branch、自动上传等设置 | 现有 SQLite 元数据，不含 PAT |
| 正在使用的 PAT | 桌面主进程与一次性原生辅助程序内存 |
| 词条、批次和回执 | 原有 SQLite 队列和确认后的私库 `captures/` |

凭证项目名为应用固定命名空间加目标 owner/repository/branch 的 SHA-256；owner 和仓库名按大小写不敏感比较，分支保留大小写。读取时再次校验记录与所选目标，不能把一个仓库的记录换到另一个仓库。

原生辅助程序通过重定向匿名管道接收/返回值，不把 Token 放到命令参数、环境变量、临时文件、URL、截图或日志。生产 IPC 的连接参数仅允许目标字段，React 界面和 preload 没有获取凭证接口；状态只返回连接状态和固定提示。Windows 保存错误不会降级成 JSON、localStorage 或 SQLite 明文保存。

当前实现使用 Windows 的本机持久 Generic Credential，不通过 Windows 账户跨机器漫游。它依赖当前 Windows 用户及系统的保护；同一用户下的恶意程序仍可能访问用户凭证，不能把它理解为硬件隔离或不可导出。复制程序或 SQLite 到另一台电脑不会复制安全凭证，需在新机器单独授权。

## 再次启动与错误处理

应用先打开本机窗口与队列，再异步读取 SQLite 中已确认目标对应的安全凭证并只读核验。成功后自动恢复会话，无需再次输入 PAT；不会因等待网络阻塞快捷键或窗口。

| 结果 | 当前处理 |
| --- | --- |
| 成功 | 恢复连接；是否上传仍受自动同步设置和正式 Web 兼容性检查限制 |
| 网络中断、超时、服务端错误、限流 | 保留安全凭证与队列，显示暂不可用，联网后可重试 |
| 403 / 权限不足 | 保留凭证，提示检查仓库与 Contents 权限，不当作 Token 失效 |
| 404 / 仓库或分支不可访问 | 保留凭证，提示检查目标；不把缺失文件当凭证无效 |
| 已保存授权返回 401 | 结束会话、删除该目标已保存凭证，进入重新授权状态 |
| Windows 安全存储不可用 | 显示凭证存储错误，不明文回退，不开启记住状态 |

前台恢复及定时重试有节流，用户也可点「重试自动连接」。需要重新授权或权限修复的状态不会每分钟反复弹出凭证窗口。自动恢复只进行核验，不绕过首次连接确认，也不初始化或覆盖主快照。

「断开连接并忘记凭证」会停止自动连接、清除本机已确认目标并删除该目标的安全凭证；队列和远端批次继续保留。删除安全记录失败会明确提示，不能宣称已删除。退出应用只结束内存会话；已选择记住的凭证仍由 Windows 保存，直到断开、明确失效或本人撤销。

从旧队列迁入时，当前连接会先断开并清除其记住的凭证，迁移后重新核对目标，避免旧设置静默激活另一个队列。迁移本身不迁移 Windows 安全凭证，也不复用曾贴到聊天的凭证。

## 与 Web 发布的关系

连接成功不表示已上传。所有桌面上传入口均先在线核对固定正式站的 `release.json`，要求采集与状态协议 1/2 及 `context-morphology` 能力。请求不带凭证、不使用 SW 缓存，不允许重定向；失败则暂停上传、保留队列。核对缓存最多五分钟。

这项门槛防止旧 Web 接收器遇到新字段；公开元数据存在本身不能代替真实部署页面的导入验收。正式站部署、真实私库上传及接收结果仍以 [整合报告](../reports/integrated/INTEGRATED_RELEASE_REPORT.md) 为准。

## 已有验证与边界

已保存的本轮证据记录了实际 Windows Credential Manager 的写入/读取/删除，以及真实 Electron 退出重启后无需再次输入的恢复流程；同时检查了 profile 和辅助程序未含人工凭证明文。网络失败保留、401 失效、断开后重启不恢复也有覆盖。

这些授权回归中的 GitHub HTTP 为人工模拟，401 是故障注入，不能称为真实 PAT 撤销测试或真实私库通过。原生系统 API 与真实进程测试、模拟 GitHub、最终真实私库测试分别记录，不混用结论。Windows 以外的平台会跳过实际安全存储用例，不冒充 Windows 验收。

本轮不需要把 Token 发给开发代理。需要本人输入时仅在已核对的原生窗口操作，不记录包含凭证的 trace 或截图。

## 0.6.1 授权窗口故障修复

0.6.0曾出现按钮停在“请完成系统授权窗口”但无可见原生窗。0.6.1将凭证helper改为GUI子系统、显式UTF-8匿名管道，交互启动不带隐藏标记。原生窗核对自身可见后发固定就绪标记；8秒未就绪则终止本次子进程并恢复操作，不等待10分钟。窗口正常显示后仍保留充足输入时间。设置页可取消授权输入，取消不误报凭证存储错误、不清除既有授权或队列。

这是启动与取消修复，不能据此推定真实PAT连接成功。Node与Electron诊断窗可见性使用无密码框、无网络/凭证访问的独立fixture验证；旧隐藏标记单独对照未复现隐藏，所以不将它断言为已证明的唯一根因。当前结果见[修复报告](../reports/integrated/AUTH_WINDOW_FIX_0_6_1.md)。

2026-10-27补验：已保存凭证真实GET成功；先备份后修复缺失的目标metadata，正常便携重启无需再次输入，实际恢复了正确连接。新事件另由独立进程从SQLite读回。此前目标缺失的根因仍未确定，不把修复后成功泛化为此前落盘完整。完整记录及真实v1/v2链路见[最新验收](../reports/integrated/CLEANUP_AND_LIVE_ACCEPTANCE_20261027.md)。
