# 同步故障与恢复

先导出完整 JSON 并确认保存。所有下面的重试均不需要清空本机；不要删除 pending、墓碑或评分事件，不要手改 SHA。云端实时状态以新 GET 为准，设置显示的快照摘要是上次成功确认值。

| 状态 | 检查与处理 |
| --- | --- |
| 未连接 / 需要重新授权 | 刷新后内存 PAT 消失是预期行为。重新填凭证并只读测试，检查目标和预览再确认。 |
| 401 / Token 失效 | 凭证已清理。检查有效期或撤销状态，在 GitHub 生成最小权限替代凭证，仅在网页输入。本机数据保留。 |
| 403 权限 / 策略 | 检查仅所选仓库 Contents 读写、组织审批、分支规则。不会无限重试，也不申请扩大无关权限。 |
| 403 限流 / 429 | 遵守可读 Retry-After / rate-limit reset；不可读头时保守至少一分钟退避。等提示时间后重试。 |
| 404 | 检查 owner/repo/branch、私有仓库访问与 Contents 权限。仓库改名不自动跟随，重新确认连接。原来已同步的文件消失会阻止自动重建，请核查 GitHub 提交历史。 |
| 409 | 本轮最多三次 SHA 重读合并，1 秒、2 秒退避；仍竞争时稍后再试，没有 force overwrite。 |
| 422 | 格式、分支规则等请求问题停止；明确 spam/secondary 限流才退避。不会把所有 422 当 SHA 冲突。 |
| 500/503、超时、断线 | 上传可能已经成功。保留持久化 batch/candidate 和 pending，下一次先读远端确认，不为同次评分生成新 ID。 |
| 另一标签页正在同步 | 等待该页完成。崩溃页租约最多 90 秒过期，不手动清表。不同设备仍通过远端 SHA 竞争。 |
| 协议/算法不兼容 | 停止读写，保存本机备份并升级到相同协议客户端。未知字段不会被裁掉后上传；不要只修改版本号。 |
| 容量超限 | 保留和导出完整数据，等待经过测试的单提交分片迁移。不要手工截断评分历史来通过大小检查。 |

## 冲突处理

同字段冲突：展开共同基线、本机和远端副本，检查差异后选择版本并二次确认。独立可编辑字段已经自动合并；决议以新 revision 及候选父修订保存，审计副本进入完整备份。之后再次同步仍验证最新 SHA，新修改不会因一次选择而获得无限覆盖权。

删除与编辑：旧 UUID 的删除永久保留；编辑副本保存在冲突/审计中。「保留删除」确认后可继续同步。若确实需要恢复内容，可从备份/审计参考手动新建词条和卡片 UUID，不能删墓碑复活旧记录。

同词同模板不同卡片 UUID：两张都停止调度，选择保留的卡片；另一张软删除、添加永久墓碑，原历史保留，不合并 FSRS 数值。

复习分叉：显示设备 UUID、时间、评分和原事件。选定合法分支后保留两侧原始事件，追加 ReviewResolution，忽略另一分支及其后继在有效统计中的贡献。选定分支的合法终点状态成为新状态；下一次评分引用 parentResolutionId 和选定终点事件，不把兄弟事件串联。不要按日期挑「更新」的一条或平均数值。若选定分支内部仍有分叉，先处理更深层分叉；复杂嵌套或并发决议无法证明唯一合法终点时停止并保留全部证据，不自动修补。

不可变同 ID 内容不同、身份变化、远端物理移除历史等完整性问题：没有选择覆盖按钮。保存本机完整 JSON，核查专用私有仓库 Git 历史和来源客户端，恢复为已知合法远端版本后重新只读检查。不应通过普通字段决议篡改历史。

## 备份、换仓库和清除

完整备份 v2 包括共享快照、本机基线/outbox、冲突、决议审计及完整冻结任务；没有 Token。旧 v1 包装只补空的新增本机集合，再做全部结构和真实 FSRS 校验。未知版本、未知字段、会丢失本机已有事件/墓碑的旧备份均拒绝。

替换恢复要求安全备份和明确确认，原子落库，保留当前设备身份；连接、凭证、旧 SHA、活动任务与租约都不继承。备份文件中的批次保留供审计，不能恢复后自动继续旧目的地上传。重新连接必须再次只读检查并合并；本机缺失记录不被解释成远端删除。清除本机也不修改 GitHub 内容。

换仓库/分支重新确认，旧连接基线不能复用。pending 和本机数据保留；建议换目标前完整导出旧工作区，审计及旧基线仍在备份中。页面发送后已经在途的远端 PUT 不能保证撤回；断开后不会再发新请求，ACK 验证连接代次，未确认本机修改保留。重要迁移请等正在同步完成。

自动同步默认关闭。开启后按本机操作批量触发，每次至少一分钟，失败最多三次自动尝试后等待新的前台/联网触发或手动操作。授权/协议/冲突问题需要人工处理，不能依赖关闭网页事件完成最后上传。

排查日志不要包含 Authorization、Token、私人响应正文或备份全文。本项目只显示固定错误分类；普通使用者无需打开开发者工具复制请求头。
