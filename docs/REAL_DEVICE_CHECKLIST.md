# Phase 3.5：真实网站与设备验收清单

当前只完成推送前准备；以下项目必须在首次 push 获批准、Actions 成功并实际访问站点后执行，不能提前勾选。

正式地址：<https://polar0216.github.io/polar-vocab/>。唯一数据测试目标：`Polar0216/polar-vocab-data-test`，必须保持 **Private**。只用人工英德词条，A/B 两端独立浏览器 profile 或设备，禁止使用已有个人词库。

## 上线与两端准备

1. 检查公开仓库 Actions 对应提交的 build/deploy 均成功，记录运行链接和提交 SHA；仅有配置文件不算上线。
2. 桌面 profile A 打开正式地址，依次进入首页、生词箱、复习、词汇库、设置并刷新，检查无404、资产错误和未保存输入丢失。
3. B 使用另一个隔离 profile 或 iPhone，不能只是同一个 profile 的第二个标签页。两端在完整 JSON 的本机 metadata 中核对 deviceId 不同；备份仅留在私人位置，不上传公开报告。
4. 在 GitHub 网页确认测试仓库 Private、已有 README 和分支。生成每设备独立 Fine-grained PAT，仅该测试仓库 Contents 读写和有限有效期。凭证只在可信网站设置页手动输入，不发聊天、日志或截图。
5. 设置 owner=`Polar0216`、repo=`polar-vocab-data-test`，已有目标分支可留空使用默认值。先「测试连接（只读）」；检查远端存在情况、预览数量与规模，下载安全备份并明确确认。已有数据不得当成空库覆盖。
6. 确认后再次同步，检查已同步/pending=0、最近成功时间和云端摘要；在测试仓库查看 `data/state.json` 及提交记录，确认没有 Token/本机 outbox/设备授权。

API 证据只记录状态码、目标、提交/文件 SHA、是否条件命中和时间，不记录 Authorization、完整请求头、Token 或私人正文。若需读开发者工具，请先隐藏凭证输入和敏感面板。没有遇到真实限流就记录「模拟覆盖，真实未触发」。

- [ ] 1. Safari 打开正式地址，五页面无白屏/404，联网等待外壳缓存完成。
- [ ] 2. 分享 → 添加到主屏幕；桌面图标和应用名称正常。
- [ ] 3. 从主屏幕启动，界面可操作，导航不遮挡按钮，无横向滚动。
- [ ] 4. 复制 `example`，在生词箱主动点「从剪贴板导入」，预览后确认，只出现一条。

- [ ] 6. 手动新增人工 EN 词条，刷新后词形/释义仍在。
- [ ] 7. 新增 DE `Prüfwort`，填写名词词性、冠词和复数，保存并重新打开核对。

- [ ] 11. 在设置手动输入仅测试仓库凭证，只读检查目标/Private，保存备份并确认连接。不要把真实 Token 发给 Codex。

可补充一份小型 Numbers CSV（中文/德语特殊字符/引号/多行）与 JSON 下载到「文件」的验证。清空和覆盖恢复只用独立人工工作区，必须保存备份和明确确认；清本机不等于清远端。

## 失败时反馈

提供页面名称、点击顺序、在线/离线、屏幕可见的固定错误、刷新前后记录数量及复现是否稳定。可反馈 GitHub Actions 链接、HTTP 状态和人工记录的事件 UUID；隐藏 Token、请求头、个人备份及无关仓库。暂停有风险的重复写入，先保留本机完整 JSON，再按 [故障手册](SYNC_TROUBLESHOOTING.md) 处理。
